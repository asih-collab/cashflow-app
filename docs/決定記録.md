## 2026-09-28 デザインの方針（利用者の要望「モダンでシックな UI」）

| 決定 | 理由 |
|---|---|
| エディトリアル（雑誌）調: 紙のような温かい下地、墨色の文字、深い緑のアクセント、数字は Instrument Serif（自前配布）、日本語見出しはヒラギノ明朝 | 「AI 開発っぽくない」見た目にするため、青いグラデーション + ゴシック体の定番構成を避けた。フォントは Latin のみ約 30KB で、Service Worker がキャッシュするためオフラインでも同じ見た目 |
| 「シックな画像」は写真ではなく SVG のアートワーク（色面 + 粒子 + 細い楕円）をコードで生成 | 写真サービスは Claude の環境から使えず、ライセンスと容量の問題もある。生成なら月ごとに絵が変わり、オフラインでも出る |
| UI フレームワークは入れない（CSS のみ） | 05 の「依存最小」。対象は iPhone 1 台で、デザインはトークン（CSS 変数）で管理すれば十分 |
| タブや削除のアイコンは絵文字をやめ、線画の SVG に統一 | 端末によって絵文字の見た目が変わるのを避ける |

## 2026-09-28 公開作業で分かったことと変更

| 決定 | 理由 |
|---|---|
| ログインは「メールのマジックリンク」を主にし、iPhone の Safari で開いたときは「ログイン情報をコピー → ホーム画面アプリに貼り付け」で引き継ぐ | Supabase の無料プラン + 標準メール送信ではメール文面を変えられず、6 桁コードを載せられない（Management API が 400 を返す）。ホーム画面アプリと Safari は保存領域が別なので、リンクだけではアプリ側にログインが残らない。コード入力欄は「文面にコードがある場合」用に残す（独自 SMTP を設定すれば使える） |
| 引き継ぎ文字列は `cf1.` + base64url の JSON。貼り付け時にサーバーで更新して有効性を確かめる | クリップボード経由・本人の端末内だけで扱う前提。サーバー側の追加実装なしで済む |
| Supabase の接続情報（URL と Publishable key）は GitHub の Variables（`SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY`）に本人が登録する | リポジトリに置くことは環境の保護機能で拒否された。Claude の環境からは GitHub の Variables 登録 API が使えない。未登録でも公開はでき、端末内のみで動く |
| GitHub Pages は `gh-pages` ブランチ方式（ビルド結果をワークフローがブランチに置く） | 「GitHub Actions」方式は Pages の有効化に管理者権限が要り、ワークフローのトークンでも Claude の環境からも有効化できず、本人の設定画面にも選択肢が出なかった。`gh-pages` ブランチは GitHub が自動で公開する |
| 本人のメールアドレスの許可リスト登録は本人が SQL Editor で行った | 「アクセス権の付与」として環境の保護機能で止められた |
| 接続情報は本人が GitHub の Secrets に登録。ワークフローは Variables と Secrets のどちらからも読む | 本人の画面で Secrets 側に入ったため |

## 2026-09-28 段階 0・1 の実装

### 実装した範囲（07 の段階 0・1）

- F01 クイック記録（テンキー → 中分類 → 保存。日付は今日、支払い手段は前回と同じ。「その他…」で全カテゴリ。詳細で日付・支払い手段・メモ。保存直後に取り消し）
- F04 カテゴリ（04 の 3 章の初期セット。使用回数順に自動で並び替え。追加・名前変更・非表示）
- F02 ホーム（今月の変動費合計、1 日あたり平均、中分類別の内訳、最近の記録と削除。予算は段階 2）
- F10 ログイン（メールのコード / マジックリンク）と Supabase 同期（オフライン時は未送信キューに残し復帰後に送信。別端末でログインすると同じデータ）
- 初回起動時の「ホーム画面に追加」案内。Safari で開いている間はホームにも案内を出す
- おまけ: `#/add?amount=1200&cat=デート` で値を渡せる（段階 3 の iOS ショートカット用）、JSON 書き出し（05 の 4.2）

### 決定と理由

| 決定 | 理由 |
|---|---|
| ログインは「メールの 6 桁コード」を主にし、マジックリンクも併用 | ホーム画面に追加した PWA と Safari は保存領域が別。メールのリンクは Safari で開くため、PWA 側にログインが残らない。コードなら PWA 内で完結する。06 の「マジックリンク」の意図（パスワード不要・メールだけ）は保っている |
| Supabase のクライアントは自前（fetch のみ、約 150 行） | 05 の「外部ライブラリは最小限」。使うのは OTP 送信・検証・トークン更新・REST の select / upsert だけ |
| 新規登録を DB 側の許可リスト（`private.allowed_emails`）で本人のメールだけに制限 | 本人専用アプリ（05 の 4.2「本人だけが開ける」）。URL は公開されるため、他人がアカウントを作れないようにする。メールアドレス自体はリポジトリに置かず、DB に直接入れる |
| 同期は「端末の updated_at で衝突解決、サーバーの synced_at で差分取得」 | 端末の時計だけに頼ると差分の取りこぼしが起きるため。サーバー側のトリガーで古い更新を捨てる |
| 初期データ（カテゴリ・支払い手段）は固定 UUID・固定の古い時刻（2000-01-01） | 2 台目の端末でも同じ行として扱われ、先に使っていた端末の変更（使用回数など）が必ず勝つ |
| 支払い手段の初期値は「クレジットカード / PayPay / 口座引落 / 現金」の汎用名 | カード名は個人情報に近いので公開リポジトリに置かない。設定で名前変更・追加できる |
| 起動時の画面は「記録（テンキー）」。設定で「ホーム」に変えられる | 04 の 4 章「起動と同時に金額入力画面」と MVP 完了条件 1。記録画面の左上に今月の合計を出し、シーン B（残額確認）も 0 タップで満たす |
| ホームの「＋ 記録する」は合計の直下。下のタブバーにも「記録」 | 06 の S1「最上部に＋記録」に従いつつ、親指の届く位置にはタブを置く |
| 「今月」の始まりの日は設定（1〜28）。初期値は暦月 | 06 の 1.3。使いながら決める |
| Publishable key はリポジトリに置かず、GitHub の Variables からビルド時に注入 | 依頼の「鍵をリポジトリに出さない」。公開前提の鍵ではあるが方針に合わせた。公開後の JS には含まれる（仕組み上避けられない。RLS で保護） |
| 自動テストは Chromium の iPhone 14 サイズで実施 | Claude の環境に WebKit が無い。実機の Safari 固有の確認は本人が行う |
| 「最近の記録」の削除をホームに置いた（F11 の一部を前倒し） | 誤記録を直せないと記録率が落ちるため。編集・過去日付入力の本体は段階 2 |

### 環境の制約で持ち越したこと

- 公開リポジトリ `asih-collab/cashflow-app` の作成（GitHub の連携に作成権限が無い）
- Supabase への SQL・Auth 設定の反映（`scripts/supabase-apply.sh` を用意。反映は本番変更のため承認が必要）
- GitHub Pages の有効化と Variables の登録（リポジトリ作成後）
